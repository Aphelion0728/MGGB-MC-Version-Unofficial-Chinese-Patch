# MGS 输入诊断

## 模拟器内部诊断层（2026-10-26）

`build_emulator_overlay.py` 从已校验的原版资源生成候选包，只替换
`system/script/play_standalone.nut.m`。进入实际游戏画面后，左上角应出现
`EMU DIAG`。其中 `Q/E` 是脚本收到的原始键，`L/R` 是系统映射后的输入，
`PL/PR` 是手柄输入，`V` 是 `EmuTaskBase.getEmuKeyCurrentOn(0)` 返回的
模拟器虚拟键位掩码。第二行 `LAST` 保留最近一次非零状态，方便截图。

先前的 `build_emulator_trace.py` 使用 Squirrel `printf`；发行版没有把该
输出送到 Windows `OutputDebugString`，因此日志只有 Steam 初始化记录，
不能据此判断模拟器是否收到按键。

候选包和原版资源的 SHA-256 必须在部署、回滚时分别校验。测试结束后
恢复 `Buckup/20261026_qe_emulator_diag_before/windata` 中的原版文件。

原版画面诊断结果：Q、E 分别到达 `g_inputKeyboard`，且转成 `g_input`
的 L、R；按键期间 `getEmuKeyCurrentOn(0)` 仍为 0，但游戏快捷菜单已
打开。普通游戏按钮会让虚拟按键掩码变为 `04` 或 `08`。因此 Q/E 是独立
于普通 Game Boy 按键掩码的快捷路径。

`build_chs_runtime_probe.py` 从发布版 `0.2beta` 资源生成汉化探针。
它用 `getRomValue(8, address)` 读出快捷路径涉及的 ROM 字节；玩家按
F8 后，只有全部字节与预期汉化 ROM 匹配，才通过 `setRomValue` 写入六
处临时补丁。`APPLIED` 表示本次进程内已写入；`MISMATCH - NOT WRITTEN`
表示没有写入。此探针只用于定位故障，不是最终汉化补丁。

## Windows 输入记录器（旧方案）

`Monitor-MGSInput.ps1` 是一个外置记录器，不会拦截输入、不注入游戏进程，也不修改游戏文件。

## 运行

在 PowerShell 中执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\tools\Monitor-MGSInput.ps1"
```

保持诊断窗口运行，切到游戏后：

1. 按 `F8` 作标记，再按 `Q`，观察 Codec 是否打开。
2. 按 `F9` 作标记，再按 `E`，观察武器/道具菜单是否打开。
3. 分别测试手柄左右扳机。
4. 切回诊断窗口按 `Ctrl+C` 结束。

CSV 默认保存在脚本目录的 `logs` 子目录中。键盘行包含按下/松开时刻及当时的前台进程和窗口标题；XInput 行记录控制器连接状态和左右扳机数值（0–255），并在数值达到 30 时标记按下。

## 诊断范围

本工具能确认 Q/E 是否到达 Windows，以及 XInput 控制器扳机是否被 Windows 识别。它不能直接读取模拟器进程内部的按键映射，也不能证明虚拟按键最终送进了游戏核心。若 Q/E 与扳机都记录正常，但原版游戏对 Q/E 无响应，下一步需对模拟器输入分发处做进程内日志/调试；这份日志可先作为原版基准，与汉化版测试结果对照。
